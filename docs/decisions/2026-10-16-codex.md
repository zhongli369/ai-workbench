## 1. 四态区分（PHASE 1 实测）

1. **CLI 存在**：`which -a codex` 仅命中 npm 全局 `codex`（0.2.3，
   `AppData/Roaming/npm/codex`），其 `--help` 显示 `build / watch / serve / skeleton`
   —— 与 OpenAI Codex CLI 无关（静态站生成器）。真 CLI 是 `codex-cli`：
   - `~/.codex/plugins/.plugin-appserver/codex.exe` → `codex-cli 0.162.0-alpha.2`（本轮使用）
   - `~/.codex/.sandbox-bin/codex.exe` → `codex-cli 0.150.0-alpha.12.2`（较旧 bundle）
   两者都真实、可执行（`--version` / `exec --help` 均正常）。SCOUT 记录的候选
   0.163.0 与实测 0.162.0-alpha.2 接近，记录为新 bundle。
2. **版本可用**：`exec --help` 提供 `-s/--sandbox <read-only|workspace-write|danger-full-access>`；
   `exec review` 提供 `--commit <SHA> / --base <BRANCH> / --uncommitted`；
   非交互（exec 默认 never-approval）。PATH 上的假 `codex` 不进入任何命令。
3. **登录态（非标准，如实记录）**：config 顶层
   `model_provider="deepseek"`、`preferred_auth_method="apikey"`、
   `forced_login_method="api"`；`[model_providers.deepseek]` 段含
   `base_url="https://api.deepseek.com/"` 与内联 `experimental_bearer_token`（键名=密钥位，
   值未读取/未打印）。首次运行在 auth.json 为 ChatGPT OAuth 时被拒（§4）。
4. **模型审查成功**：见 §3。

## 2. 实测命令（exact verified command line）

```bash
# 要求：cwd = repo 根；真 CLI 绝对路径；非交互；sandbox read-only；无写入
CODE="$(cygpath -u "$USERPROFILE")/.codex/plugins/.plugin-appserver/codex.exe"
"$CODE" exec review --commit 98bcdae --ephemeral \
  -c sandbox_mode=read-only -c 'notify=[]'
```

要点（均来自 `--help` 实测 + 真实运行）：`--commit` 与位置参数 prompt 互斥（错误：
`argument '--commit <SHA>' cannot be used with '[PROMPT]'`），故只传 commit，用内置审查指令；
`-c sandbox_mode=read-only` 为官方只读模式；`-c notify=[]` 跳过本机 turn-end notify
钩子（指向 `codex-computer-use.exe`，否则进程在出答案后仍挂起——探针运行曾因此被停）；
`--ephemeral` 不落 session 文件；review 子命令**没有** `-C/--cd`，必须从 repo 根运行。

## 4. 副作用披露（如实记录）

首跑（auth 冲突时）输出：`API key login is required, but ChatGPT is currently being
used. Logging out.`，CLI **删除了 `~/.codex/auth.json`**（其中曾存放 ChatGPT OAuth 凭据，
3833 字节，8-24 存在——本轮被登出移除）。此后无冲突凭据，deepseek provider 经内联
token 正常工作。处理原则：不触发任何登录/重新登录；不臆造凭据；如再遇该报错，
如实报告并交由用户处理其 Codex 登录态。**永不读取/打印任何 token 值。**
